# APCOSYS Design Library — UX/UI audit

Date: 2026-10-09
Scope: documentation, catalog of 28 components, visual engines, tokens, icon browser, search, mobile and desktop, both color themes.
Goal: a small, predictable interface for designers and developers. No new visual language or unnecessary controls.

## Core finding

The largest usability cost was duplication rather than missing features: two routes to inspect each component, duplicate catalog navigation, technical labels on every tile, an extra action for icon copying, and the same headings repeated on focused documentation pages.

The target interaction is: find → inspect → use. Keep source code available, but do not require opening a modal before reaching a component's real page.

## Changes, ordered by priority

| Level | Previously | Change |
| --- | --- | --- |
| P0 | Grid card opened an inspector modal, then a separate detailed page | One link opens the dedicated component page directly. Code and source stay on that page, with code under an expandable section |
| P0 | Icon selection opened a fixed overlay and required another click to copy | One click copies usage code. If browser permissions deny access, a compact inline field shows the selectable code |
| P1 | Component categories and icon families repeated in sidebar and page controls | Sidebar has simple section links; filters live beside their catalogs |
| P1 | Per-card technical footer and two identical entry points | One header link, one live preview, no repeated category footer |
| P1 | Everyday interface patterns appeared after decorative engines | Interface first, product demonstrations second, visual effects last |
| P1 | Global search could list several color tokens with the same destination | Unique destinations and a maximum of eight visible results |
| P1 | Focused tokens page repeated “Brand styles” above its own heading | One semantic page H1, while the complete Brand styles overview retains its hierarchy |
| P1 | Empty search results provided no recovery path | “Clear filters” / “Clear search” only in the empty state |
| P2 | Equal HEX values could mark multiple token rows “Copied” | Copy feedback is tied to the semantic token, not to the duplicated value |
| P2 | The home page repeated navigation and promotional copy | Four direct entry points, no redundant “More to explore” block |

## Explicitly preserved

- Published APCOSYS typography, colors, logo geometry and theme semantics.
- React components, motion engines and original styling of product controls.
- Semantic code exports and source links, deep-linked routes, keyboard search.
- Reduced-motion behavior, lazy/offscreen rendering of gallery animations.
- Native mobile sidebar and full-width responsive content layout.
- External website references remain absent from the library UI.

## Verification

GitHub Actions on this branch: 24/24 Playwright UX/browser tests; design-system token test covers 17 semantic colors in both themes, 286 Feather icons, 1527 Phosphor icons and four brand assets.

## Next tasks, deliberately excluded from this pass

1. Independent WCAG screen-reader and color-contrast testing beyond current behavioral coverage.
2. Snapshot-based pixel equivalence of interactive controls across all breakpoints and both themes.
3. Consolidation of legacy overlapping CSS rules without changing approved rendering.
4. Better distributable packaging/import guides, should the source-first repository become an npm package.

Do not add controls or panels to address these tasks without a specific use case.
